01

이 화면이 답해야 하는 질문 3가지

모든 패널은 아래 세 질문 중 하나에 답하기 위해 존재한다. 장식적인 패널은 넣지 않는다.

Q1

지금까지 실행에 토큰/비용이 얼마나 들었나?

Q2

스키마를 전체 덤프 대신 검색으로 줄인 게 실제로 비용을 줄였나?

Q3

쉬운 질문은 저비용 모델로, 어려운 질문은 고성능 모델로 실제로 갈리고 있나?

02

데이터 소스

화면을 채우는 백엔드 엔드포인트 2개 — 로딩/빈 상태 설계 시 참고.

GET /cost/summary
Zone B, C의 데이터 소스. group_by 파라미터로 비교 축을 바꿔 같은 모양의 응답을 재사용 — schema_rag_mode면 Zone B, difficulty면 Zone C.
GET /runs/{id}/cost
Zone D의 목록 + 행 클릭 시 드릴다운(노드별 호출 내역)의 데이터 소스.
03

화면 구성 — 4존

점선 박스 = 실제로 그려야 할 영역, 안쪽 목업 = 톤·정보 밀도 참고용(치수·색은 자유, 배치와 강조 우선순위만 유지). Zone B의 수치는 docs/kpi-schema-rag-mode-ablation.md 실측값을 그대로 썼다 — 실 데이터 기준.

04

상태 처리

도메인 관리 화면의 로딩(skeleton)/에러 패턴을 그대로 재사용.

로딩도메인 관리 화면의 skeleton-line과 동일한 스타일로 Zone A~D 자리에 펄스 애니메이션.
데이터 없음아직 실행 기록이 없는 신규 도메인 — "첫 질의를 실행하면 여기 비용이 쌓입니다" + 질의 실행 화면 링크.
에러app-db 연결 실패 시 도메인 관리 화면과 동일한 적색 에러 배너 + 재시도 버튼.
